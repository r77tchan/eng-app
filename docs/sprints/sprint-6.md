## Sprint 6: 「わからない」回答・セッション中断・問題プール 300 問拡張

### 目的

ユーザーの学習体験を「正解か誤答か」の二択から「正解 / 誤答 / わからない」の三択に拡張し、適当に答えることへの心理的負担を下げる。あわせてセッション途中で離脱したいユーザー向けに中断導線を用意し、問題プールも 60 問から 300 問へ拡張して長期利用に耐える供給量を確保する。本スプリントの 3 機能はいずれも「セッション中の解答フロー」または「セッション中に消費される出題データ」に関わり相互依存があるため、同一スプリントで合わせて実装する。

### 前提

- Sprint 1〜5 が完了していること（学習サイクル、履歴、復習キュー、カテゴリ・難易度選択、設定画面、PWA、GitHub Pages デプロイが全て動作していること）
- 既存 `lib/questions.ts` のスキーマ（id / word / answer / choices / category / difficulty）を維持すること
- 既存 `lib/history.ts` の `AnswerRecord` スキーマは後方互換を保つこと（既存ユーザーの LocalStorage を壊さない）

### 実装する機能

- **問題プール 300 問拡張**: `/public/data/questions.json` の問題数を現在の 60 問から **300 問以上**に増やす。カテゴリ 4 種・難易度 3 種の各組合せ（合計 12 組合せ）にそれぞれ最低 20 問以上を配置する
- **「わからない」回答**: 学習セッション画面に「わからない」ボタンを 4 択の下に配置し、タップすると誤答とは別カウントで履歴に記録する。復習キューには追加する
- **セッション中断ボタン**: 学習セッション画面の上部に中断ボタンを設置。タップすると確認モーダルが表示され、確認するとホーム画面に戻る。中断時点まで解答済みの問題は履歴・復習キューに反映済みであり、新たな副作用は発生しない
- **結果画面への「わからない」件数表示**: セッション結果画面に「わからない: N 問」を表示する

### 設計判断（理由つき）

- **名称は「わからない」を採用**: ユーザーの動機は「適当に当てたくない」という誠実な意思表示であり、「スキップ（飛ばす）」よりも「わからない（分からないと答える）」の方が動機に忠実なため
- **誤答とは別カウント**: 既存の `correct: boolean` を `false` のままにしつつ、新規フィールド `skipped: boolean` を `AnswerRecord` に追加する（後方互換を保つため `undefined` は `false` 扱い）。これにより既存の集計関数（`getTodayStats` / `getStreak` / `getDailyStats`）の挙動は変えずに、結果画面でのみ「わからない」を区別して表示できる
- **復習キューには追加**: 「分からない問題こそ復習対象」という学習効果重視の判断。誤答と同じく `addToReviewQueue` を呼ぶ
- **ストリーク・今日の学習問題数にはカウント**: 学習行動は成立しているため、既存のロジック（解答 1 件以上で当日学習扱い）に自然に乗る
- **正答率の分母には含めるが、結果画面では別表示**: 既存の集計関数（`accuracyPercent`）は `correct` フラグだけを見ているので変更不要。「わからない」は誤答扱いで分母・分子に反映される。ただし結果画面では「わからない: N 問」を独立表示し、ユーザーに区別を見せる
- **中断時の挙動**: 中断は副作用を起こさない（既に解答した問題の履歴・復習キュー反映は解答時点で完了している）。中断専用の履歴レコードは追加しない。確認モーダル必須（誤タップ防止、特に車内での揺れ対策）
- **問題プール 300 問の根拠**: カテゴリ 4 × 難易度 3 = 12 組合せに各 20 問以上 = 240 問が下限。300 問なら平均 25 問前後となり、復習キューに 100 問規模で溜まっても新規供給が枯れず、長期利用に耐える
- **わからないボタンの配置**: 4 択ボタンの下に「控えめに」配置し、誤タップを防ぐ。ただしタップ領域は 44×44px を確保する
- **中断ボタンの配置**: 画面上部右寄せ。学習動線（下半分の親指リーチ）を邪魔せず、かつ確認モーダルを介すので片手で「次へ」を押すときに誤タップしても安全

### スプリント契約（完了条件）

以下の全条件を満たした場合のみ、このスプリントは完了とする。

#### 問題プール拡張

- [ ] `/public/data/questions.json` に少なくとも **300 問** の英単語 4 択問題が格納されている
- [ ] 全 300 問以上に `id` / `word` / `answer` / `choices`（4 つ）/ `category` / `difficulty` が揃っている
- [ ] カテゴリ × 難易度の 12 組合せ（daily/business/travel/exam × beginner/intermediate/advanced）それぞれに **最低 20 問以上** が割り当てられている
- [ ] `id` は全問でユニークである（既存の `q001`〜`q060` と衝突しない連番、例: `q001`〜`q300` 以上）
- [ ] `choices` 配列には `answer` が必ず含まれ、配列要素は 4 つ重複なし
- [ ] 既存の `loadQuestionPool()` のバリデーションを通過し、不正な問題が混入していない
- [ ] `npm run build` 時に問題プールがバンドル／コピーされ、GitHub Pages の公開 URL から `questions.json` が 404 にならず取得できる

#### 「わからない」回答

- [ ] 学習セッション画面に `data-testid="dont-know-button"` を持つ「わからない」ボタンが表示される
- [ ] 「わからない」ボタンは 4 択ボタンの下に配置されている（4 択より上には来ない）
- [ ] 「わからない」ボタンのタップ可能領域は **44×44px 以上**である
- [ ] 「わからない」をタップすると、4 択をタップしたときと同じく即時にフィードバック画面に遷移する
- [ ] フィードバック画面では正解の選択肢がハイライトされ、ユーザーの選択は「わからない」だったことが視覚的に明示される（例: 「わからないと回答しました」のメッセージ、または 4 択のいずれも「ユーザー選択」状態にならない）
- [ ] 「わからない」と回答した問題は誤答扱いではあるが、`AnswerRecord` に `skipped: true` で記録される
- [ ] `AnswerRecord` の TypeScript 型に `skipped?: boolean`（オプショナル）が追加されている
- [ ] 既存の LocalStorage に `skipped` フィールドのないレコードが残っていても、読み込み時にエラーにならず `skipped: false` として扱われる
- [ ] 「わからない」と回答した問題は復習キューに追加される
- [ ] 「わからない」と回答した時点で復習キューに既にあった問題は、復習キューから除外**されない**（誤答と同じ扱い）
- [ ] 「わからない」と回答したセッションも、今日の学習問題数・ストリークにカウントされる
- [ ] フィードバック画面の「次へ」ボタンは「わからない」回答時にも表示され、押下で次の問題（または結果画面）へ遷移する
- [ ] フィードバック表示中は「わからない」ボタンが連打できない（disabled になる）

#### 結果画面の表示

- [ ] セッション結果画面に `data-testid="result-skipped"` を持つ要素があり、そのセッションで「わからない」と回答した問題数が表示される（0 問でも「わからない: 0 問」のように明示）
- [ ] 結果画面の正答数表示は従来通り（「わからない」は誤答にカウントされた状態で表示）
- [ ] 結果画面の「復習に追加」件数には、「わからない」回答により追加された問題数が含まれる
- [ ] 375px 幅で結果画面の追加表示が横スクロールなしに収まる

#### セッション中断

- [ ] 学習セッション画面（問題出題中・フィードバック表示中の両方）に `data-testid="abort-button"` を持つ中断ボタンが表示される
- [ ] 中断ボタンは画面上部に配置され、4 択ボタンと重ならない
- [ ] 中断ボタンのタップ可能領域は **44×44px 以上**である
- [ ] 中断ボタンをタップすると、`data-testid="abort-confirm-dialog"` を持つ確認モーダル（または同等のダイアログ）が表示される
- [ ] 確認モーダルには「中断する」と「続ける（キャンセル）」の 2 つの選択肢がある
- [ ] 「続ける」を選ぶとモーダルが閉じ、セッションは中断前の状態（問題番号・選択肢のシャッフル順・フィードバック表示の有無）が維持される
- [ ] 「中断する」を選ぶとホーム画面（`/`）に遷移する
- [ ] 中断前に解答済みの問題の履歴（`AnswerRecord`）は LocalStorage に保存されたままになっている（中断によって取り消されない）
- [ ] 中断前に追加された復習キュー（誤答 / わからない）も維持される
- [ ] 中断後、ホーム画面の「今日の学習問題数」「正答率」「ストリーク」が中断前に解答した分だけ更新されている
- [ ] 中断ボタンはセッション結果画面（5 問完了後）には表示されない（既に完了しているため不要）
- [ ] 確認モーダル表示中はモーダル背景に下の UI が透ける（または明確に区別される）形で、誤タップでセッションが進まない
- [ ] セッション結果画面に中断中フラグは残らない（次回セッションは通常通り 5 問から開始）
