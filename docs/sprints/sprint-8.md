## Sprint 8: PC キーボード操作対応

### 目的

PC ブラウザでアプリを開いたユーザーが、マウス操作なしでキーボードだけで学習を完結できるようにする。スマホ片手操作（Sprint 1〜7 の主要な体験）を保ちつつ、PC ユーザーには通勤外（自宅・職場休憩中）の利用シーンを提供する。アクセシビリティの観点でも、キーボード操作と適切な `aria` 属性は必須要件である。

### 前提

- Sprint 7 が完了していること（音声再生・「わからない」回答・セッション中断・問題プール 120 問が全て動作していること）
- 既存のタップ操作（4 択タップ / 「次へ」タップ / 「わからない」タップ / 中断ボタンタップ / 再生ボタンタップ）は一切壊さないこと
- スマホでの体験を変えないこと（キーボードはあくまで PC 向け補助動線）

### 実装する機能

- **数字キー 1〜4 で 4 択を選択**: 学習セッション画面（問題表示中）で `1` / `2` / `3` / `4` を押すと該当の選択肢が選ばれる
- **Enter キーで「次へ」**: フィードバック表示中に `Enter` を押すと次の問題（または結果画面）へ遷移する
- **Space キーで「わからない」**: 学習セッション画面（問題表示中）で `Space` を押すと「わからない」回答となる
- **Escape キーでセッション中断確認**: 学習セッション画面で `Escape` を押すと中断確認モーダルが開く（モーダル表示中に `Escape` を押すとモーダルが閉じる）
- **再生ボタンへの R キー（任意）**: 単語の再再生を `R` キーでも呼べる（Sprint 7 の再生ボタンと等価）
- **アクセシビリティ属性**: 各操作キーを `aria-keyshortcuts` 属性で機械可読にし、フォーカス管理を整える

### 設計判断（理由つき）

- **「Space」を「わからない」に割り当てる根拠**:
  - 最初は `S` キーを検討したが、IME（日本語入力）がオン状態のときに `S` を押すと文字入力に取られる可能性がある。`Space` は IME がオフの状態に近い動作で、PC ユーザーが両手でキーボードに置いたとき押しやすい
  - `Space` はページスクロールに使われがちだが、学習セッション画面は基本スクロール不要（375px〜PC 幅でも 1 画面に収める設計）なので衝突しない。念のため `event.preventDefault()` でデフォルト動作を抑制する
- **`Enter` を「次へ」に**: フィードバック表示中の「次へ」は学習動線の主アクションなので、フォーカス位置によらず `Enter` で進めるようにする。`window` レベルの keydown リスナで実装
- **`Escape` を中断に**: ブラウザの慣習（モーダルを閉じる、操作を取り消す）と整合し、自然に習得できる
- **`R` キーで再再生**: 任意（必須契約は数字 / Enter / Space / Escape の 4 系統）。実装余裕があれば追加する形にする
- **ホーム画面・履歴画面・設定画面ではキーバインドを有効にしない**: 副作用を限定するため、学習セッション画面のみで `window.addEventListener` を張り、アンマウント時に必ず外す
- **IME 入力中はバインドを発火させない**: `event.isComposing === true` または `event.keyCode === 229` のときは無視する。これにより設定画面等で将来テキスト入力が増えても安全
- **修飾キーとの衝突回避**: `event.metaKey` / `event.ctrlKey` / `event.altKey` が押されている場合はバインドを発火させない（ブラウザショートカットを優先）
- **入力フォーカスが `<input>` / `<textarea>` / `[contenteditable]` のときも発火させない**: 学習セッション画面に入力欄は無いが、将来の拡張を考慮した安全策
- **フォーカス管理**: 問題が切り替わった直後、4 択ボタンの最初の要素にフォーカスを当てる… のではなく、`<main>` 要素にプログラム的にフォーカスを設定し、`tabindex="-1"` で受け取れるようにする（スクリーンリーダー対応）。4 択ボタン自体は Tab キーで巡回可能なフォーカスを持つ
- **`aria-keyshortcuts` の付与**: 各操作ボタンに対応するキーを宣言する（例: 1 番目の選択肢 `aria-keyshortcuts="1"`、次へ `aria-keyshortcuts="Enter"`、わからない `aria-keyshortcuts="Space"`、中断 `aria-keyshortcuts="Escape"`）
- **操作キーの視覚的ヒント**: 各 4 択ボタンには既に番号バッジ（1〜4）が表示されているのでキー対応は自明。フィードバック中の「次へ」ボタンには `Enter` のヒント表示、「わからない」には `Space` のヒント表示を、PC 幅（例: `md:` ブレークポイント以上）でのみ控えめに見せる（スマホ画面は変えない）

### スプリント契約（完了条件）

以下の全条件を満たした場合のみ、このスプリントは完了とする。

#### 数字キーによる選択肢選択

- [ ] 学習セッション画面（問題表示中）で `1` キーを押すと、画面上 1 番目の選択肢が選ばれ、4 択をタップしたときと同じフィードバックが表示される
- [ ] 同様に `2` / `3` / `4` で 2/3/4 番目の選択肢が選ばれる
- [ ] フィードバック表示中に `1`〜`4` を押しても何も起きない（連打防止）
- [ ] 数字キーの選択処理は、対応する選択肢が DOM 上で `disabled` のときは発火しない
- [ ] 数字キー押下後は、対応する選択肢ボタンに視覚的フォーカス（または選択状態）が反映される

#### Enter キーによる「次へ」

- [ ] フィードバック表示中に `Enter` を押すと、「次へ」をタップしたときと同じく次の問題に遷移する
- [ ] 5 問目のフィードバック表示中に `Enter` を押すと、結果画面に遷移する
- [ ] 問題表示中（4 択未回答時）に `Enter` を押しても何も起きない
- [ ] 結果画面で `Enter` を押しても「もう 1 セット」が誤動作しない（明示的に発火させない／または `Enter` で「もう 1 セット」を発火しても安全）。本契約では「結果画面では Enter にキーバインドを張らない」を採用する

#### Space キーによる「わからない」

- [ ] 学習セッション画面（問題表示中）で `Space` を押すと、「わからない」ボタンをタップしたときと同じく `skipped: true` で履歴に記録され、フィードバック画面に遷移する
- [ ] `Space` 押下時、ブラウザのデフォルト動作（ページスクロール等）は `event.preventDefault()` で抑制される
- [ ] フィードバック表示中に `Space` を押しても何も起きない（誤動作防止）

#### Escape キーによるセッション中断

- [ ] 学習セッション画面（問題表示中・フィードバック表示中の両方）で `Escape` を押すと、中断確認モーダル（Sprint 6 で実装した `data-testid="abort-confirm-dialog"`）が表示される
- [ ] 中断確認モーダルが表示されている間に `Escape` を押すと、モーダルが閉じてセッション継続する
- [ ] モーダル表示中、`Tab` キーでモーダル内の「中断する」「続ける」ボタンを巡回でき、フォーカスがモーダル外に逃げない（focus trap）
- [ ] モーダル内の「中断する」ボタンがフォーカスを持っている状態で `Enter` を押すとホーム画面に遷移する
- [ ] モーダル内の「続ける」ボタンがフォーカスを持っている状態で `Enter` を押すとモーダルが閉じる

#### 入力衝突回避

- [ ] IME による入力中（`event.isComposing === true`）はキーバインドが発火しない
- [ ] `Ctrl` / `Cmd` / `Alt` 修飾キーと組み合わせた場合（例: `Cmd+1` でブラウザのタブ切替）はバインドが発火しない
- [ ] アクティブな要素が `<input>` / `<textarea>` / `[contenteditable]` の場合、本スプリントで追加するキーバインドは発火しない（現状そのような要素は学習セッション画面に無いが、将来の拡張に備えた防御）
- [ ] キーバインドは学習セッション画面（`/session`）でのみ有効で、ホーム / 履歴 / 設定 / 開始（カテゴリ難易度選択）の各画面では発火しない
- [ ] 学習セッション画面のアンマウント時に `window` の keydown リスナが必ず削除される（メモリリーク・他画面誤発火を防ぐ）

#### アクセシビリティ

- [ ] 4 択ボタンそれぞれに `aria-keyshortcuts` 属性が付与され、対応する番号（"1" / "2" / "3" / "4"）が宣言されている
- [ ] 「わからない」ボタンに `aria-keyshortcuts="Space"` または `" "` が付与されている
- [ ] 「次へ」ボタンに `aria-keyshortcuts="Enter"` が付与されている
- [ ] 中断ボタンに `aria-keyshortcuts="Escape"` が付与されている
- [ ] 中断確認モーダルが `role="dialog"` および `aria-modal="true"` を持ち、`aria-labelledby` でタイトルを参照している
- [ ] 4 択ボタン・「わからない」ボタン・「次へ」ボタンは `Tab` キーでフォーカス巡回でき、`Enter` または `Space` で発火する標準動作が維持される（つまり選択肢ボタンに `Tab` で到達 → `Enter` でも回答できる、というブラウザ既定動作を壊さない）

#### 視覚的フィードバック（任意項目を含む）

- [ ] PC 幅（768px 以上）で表示したとき、「次へ」ボタンに `Enter` 押下を示唆するヒント（例: 小さく `Enter` 表記、アイコン、kbd 要素など）が表示される。スマホ幅（767px 以下）では表示しない（既存スマホ UI を壊さない）
- [ ] PC 幅（768px 以上）で表示したとき、「わからない」ボタンに `Space` 押下を示唆するヒントが控えめに表示される
- [ ] 上記ヒントは Sprint 1〜7 のデザイントーン（design-tokens 準拠の色 / mono フォント / 控えめなコントラスト）と整合する
