## Sprint 1: MVP — 1 セッション完結する学習体験 + 静的書き出し基盤

### 目的

ログインなし・データベースなしの状態で、「問題を解いて結果を見る」という学習サイクルが 1 セッション完結することを最優先に実装する。あわせて、Sprint 1 完了時点で `next build` によって GitHub Pages にそのままデプロイ可能な静的ファイル群（`out/`）が生成される状態にする。

### 実装する機能

- **問題プール（同梱 JSON）**: アプリに同梱した JSON ファイルから 10 問以上の英単語 4 択問題を読み込む
- **ホーム画面**: アプリのトップ画面。「学習を始める」ボタン 1 つを大きく表示
- **学習セッション画面**: 5 問を順次出題し、ユーザーが 4 択から選んだ解答に対して正誤フィードバックを表示
- **セッション結果画面**: 5 問終了後、正答数と「もう 1 セット」「ホームに戻る」のアクションを表示
- **静的書き出し設定**: Next.js を `output: 'export'` で動作させ、GitHub Pages のサブパス配信に対応する設定を施す

### スプリント契約（完了条件）

以下の全条件を満たした場合のみ、このスプリントは完了とする。

#### 学習サイクル

- [ ] アプリのルート（トップ）にアクセスするとホーム画面が表示される
- [ ] ホーム画面に「学習を始める」という文言を含むボタンが 1 つだけ大きく表示されている
- [ ] 「学習を始める」ボタンをタップすると学習セッション画面に遷移する
- [ ] 学習セッション画面には、問題文（英単語）と 4 つの選択肢ボタンが表示される
- [ ] 学習セッション画面の上部に、現在何問目かが分かる進捗表示（例: 「1 / 5」）がある
- [ ] 4 択のうち 1 つをタップすると、即時に正誤フィードバック（正解か不正解かの視覚表示）が現れる
- [ ] 正誤フィードバック表示中に「次へ」ボタンが画面下部に現れ、タップすると次の問題に遷移する
- [ ] 5 問目に回答して「次へ」をタップすると、セッション結果画面に遷移する
- [ ] セッション結果画面には「◯問中△問正解」の形式で正答数が表示される
- [ ] セッション結果画面に「もう 1 セット」ボタンがあり、タップすると新しいセッションが始まる
- [ ] セッション結果画面に「ホームに戻る」ボタンがあり、タップするとホーム画面に戻る

#### 問題データ（JSON）

- [ ] 問題プールはリポジトリ内の JSON 静的ファイル（例: `/public/data/questions.json` または `/src/data/questions.json`）として管理されている
- [ ] 問題プールには少なくとも 10 問の英単語 4 択問題が用意されており、毎セッション 5 問が出題される
- [ ] 同じ 1 セッション内で同じ問題が 2 回以上出題されない
- [ ] JSON ファイル以外の場所（クラウド DB、認証付き API など）から問題を取得していない

#### 片手操作 UI

- [ ] 全ての主要操作ボタン（学習を始める / 4 択 / 次へ / もう 1 セット / ホームに戻る）は画面の縦方向中央より下に配置されている
- [ ] 全ての主要操作ボタンのタップ可能領域は最小 44x44px 以上である
- [ ] 375px 幅（iPhone SE 相当）のビューポートで、横スクロールが発生せず全要素が収まる

#### 静的書き出し / GitHub Pages 対応

- [ ] `next.config.ts`（または同等の設定ファイル）に `output: 'export'` が設定されている
- [ ] GitHub Pages のサブパス配信を想定した `basePath` および `assetPrefix` の設定が記述されている（環境変数等で切り替え可能でもよい）
- [ ] `npm run build` を実行すると `out/` ディレクトリが生成され、その中に少なくともトップページ・セッション画面・結果画面の HTML/JS/CSS が含まれている
- [ ] 生成された `out/` を任意の静的ファイルサーバーで配信すると、トップから学習セッション完了まで一連の操作が完走できる
- [ ] サーバー専用機能（Server Actions、dynamic Route Handlers、middleware、ISR、デフォルトの `next/image` 最適化）を一切使用していない
- [ ] `package.json` に静的書き出し用の build / export スクリプトが用意されており、README またはコメントから手順が読み取れる
